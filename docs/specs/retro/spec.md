# Спека: ретроспектива change и одной сессии

## facts — Фактический слой

part: устройство
refs: tasks#model

- `change retro-facts c#N` детерминированно собирает факты change и сохраняет
  полный JSON в каталоге данных приложения `retro/cN-facts.json`.
- Код считает задачи, статусы, привязки сессий, реплики и интервалы, контекст,
  повторные чтения, делегирования, компакты, попытки, парковки, коммиты и
  стоимость по ролям. Агент не пересчитывает эти величины.
- Для эвристик сессии код отдельно отдаёт долю `cache_create`, переходы между
  моделями и их число, холодные старты не на первом ходу (`cache_read = 0`,
  `cache_create > 10K`) и ходы с output больше 5000 токенов без `tool_use`.
- Повторное чтение, компакт или прерывание — сырой факт, а не автоматический
  отрицательный компонент. Отрицательное суждение требует отдельной улики.
- Файл также содержит `completion_chains` по задачам, реестр `signals` со
  стабильными id и `coverage.cannot_claim`. Цепочка различает закрытие раннером,
  вне раннера после его остановки, human gate, сессию и незакрытый статус.

## agent — Запуск анализа

part: требования
refs: providers#routing

- `change retro c#N` сначала обновляет факты, затем запускает duty `retro` через
  общий провайдерский адаптер. Стартовый профиль — Codex
  (`openai/gpt-5.6-sol`), режим — `agent`.
- Процесс агента получает prompt через stdin; после передачи stdin закрывается.
  Sandbox всегда `read-only`, для Claude разрешены только инструменты чтения.
- Метод анализа целиком хранится в `duties.retro.instructions` манифеста
  `agent-providers.json` и редактируется в маппере «обязанность → модель».
  Пользовательский текст заменяет метод целиком. В коде остаётся только
  неизменяемый контракт JSON-конверта, поэтому правка метода не ломает разбор.
- Метод проверяет контекст выше 150K, долю `cache_create` выше 15%, два и более
  компакта, холодные старты, смены модели, многословные ходы без инструментов,
  повторные чтения, прерывания и переформулировки. Затем он даёт исход каждому
  сигналу (`episode id`, `noise` или `no_data`) и группирует проблемы в эпизоды
  нарушения конкретного ожидаемого контракта.
- Анализ состоит из эффективности, разметки всех реплик, карточек задач по
  контракту измерений и двух workflow — процесса change и исполнителя задачи.
  В каждом workflow есть «как было», «как надо» и проверяемая разница.
- В отношениях без знаменателя записывается `null`. Компоненты score имеют знак
  и evidence, но не суммируются, пока не утверждены веса.

## labels — Метки реплик

part: контракт

Допустимы ровно `directive`, `approval`, `correction`, `approach_challenge`,
`defect_report`, `side_question`, `new_task`, `ambiguous`. Различение указания,
исправления и дефекта опирается на действия агента до и после реплики.

## output — Отчёт и предложения

part: данные

- Ответ агента — JSON-конверт с Markdown в `report`, массивом `episodes`, полной
  картой `signal_dispositions` и массивом `proposals`.
  Отчёт сохраняется в каталоге данных приложения как `retro/cN-report.md`.
- Эпизод хранит `expected`, `observed`, `signal_refs`, исход и `detection_gap`:
  ранний `observable`, первое распознавание (`signal` и `by`), проявление
  `reached_user` и объяснение `why_late`. Для `fixed` и `deferred` эти три
  момента не смешиваются. Сработавшая остановка раннера после review/check не
  считается разрывом обнаружения.
- Каждое предложение в `change.ext.retro.proposals` имеет поля `id`, `type`,
  `addressee`, `what`, `episode_refs`, краткие `episodes`, `intervention`,
  `measure`, `evidence`, `status`. `addressee` — одна роль: `architect`,
  `critic`, `worker`, `review` или `human`; кто именно и где — в `what`.
  `measure` — объект с полями `cases`,
  `baseline`, `observe`, `source`, `fails_if`; новый элемент получает
  `status: proposed`.
- Тип `процесс` означает переносимое изменение брифа, разбиения, проверки,
  делегирования или харнесса. Тип `инвариант проекта` означает проверяемый факт,
  обязательный именно для данного проекта.
- Допустимо не больше шести предложений за запуск; все обязательные строки
  должны быть непустыми. Новые предложения дописываются, существующие решения
  не перезаписываются.
- `change retro --session <guid>` строит факты только из указанного транскрипта
  и сохраняет facts и report в каталоге данных приложения. Change и доска для
  этого режима не нужны, предложения в карточки никогда не пишутся.

## malformed-output — Неразбираемый ответ

part: ошибки

Если агент вернул текст, который нельзя разобрать целиком по контракту, пропустил
хотя бы один signal disposition или сослался на отсутствующий эпизод, сырой текст
всё равно сохраняется как отчёт. Ни одно предложение этого запуска не пишется,
а CLI явно сообщает о неразбираемом ответе. Частичная запись запрещена.
Ошибка запуска провайдера также сохраняется диагностическим отчётом и завершает
команду ошибкой.
