# Спека: Claude Usage Tracker (обзор продукта)

> Обзорная спека: что продукт обещает пользователю. Правила жанра —
> [README.md](../README.md). Детальная спека подсистемы задач — домен `tasks`
> (`docs/specs/tasks/spec.md`).

## purpose — Назначение

part: требования

Windows-приложение в системном трее: в реальном времени показывает лимиты
расхода Claude, прогнозирует их исчерпание, ведёт локальную аналитику
эффективности Claude Code и встроенный менеджер задач, синхронизированный с
сессиями Claude Code.

Базовый контур работает локально и общается только с claude.ai (usage API) и
status.claude.com (мониторинг инцидентов). Это не единственный сетевой канал
приложения целиком: opt-in интеграция с внешним трекером задач добавляет ещё
одно направление — раздел `storage` описывает его честно, без смягчения.

## limits — Мониторинг лимитов

part: требования

- Поллинг usage API claude.ai по sessionKey + organization UUID; интервал
  настраивается (10–300 с, по умолчанию 60).
- Показываемые лимиты: 5-часовое окно, недельное окно, плюс недельные
  Opus/Sonnet-окна, когда план их отдаёт.
- План аккаунта (Pro / Max 5× / Max 20×) **выводится из состава окон**,
  которые вернул API, а не задаётся пользователем. План и окно — разные
  вещи: смена плана не меняет семантику окон.
- Показываются также платные надстройки, когда присутствуют: extra usage
  (pay-as-you-go) и prepaid-баланс.
- До сброса окна идёт обратный отсчёт («Resets in 4h 8m (Today 14:10)»),
  даты локализованы.
- Уровни расхода подсвечиваются цветом; пороги настраиваются отдельно для
  сессионного и недельного окна.

## forecast — Форекаст и бюджет

part: требования

- Прогноз исчерпания каждого окна строится от скользящего среднего темпа
  расхода (окно усреднения настраивается) с индикатором темпа «ok / warn».
- Карточка 5-часового окна дополнительно реагирует на всплеск: при резком
  росте расхода прогноз пересчитывается по недавнему темпу, а не только по
  среднему.
- Дневной бюджет (опционально, `daily_budget_enabled`): рекомендованная
  сумма равномерно размазывает остаток недельного лимита до сброса — в
  процентах лимита, либо в долларах, когда включена аналитика Claude Code.

## notifications — Уведомления

part: требования
refs: tasks#ui

- Пороговые и форекаст-алерты, настраиваемые по окну и типу алерта.
- Quiet hours и временный mute/фокус.
- Мониторинг status.claude.com: уведомление при инциденте или деградации.
- Отдельные уведомления менеджера задач — при переходе задачи в review или
  done; устройство самого менеджера задач — `tasks#ui`.

## windows — Окна

part: требования
refs: tasks#ui

| Окно | Поведение |
|---|---|
| tray flyout (main) | основная панель у трея; можно закрепить |
| mini | компактный always-on-top виджет; опционально CPU/RAM системы |
| analytics | аналитика эффективности (opt-in) |
| tasks (todos) | менеджер задач: Kanban + граф |
| settings | настройки, вкладками (включая интеграции — `storage`) |

Приложение живёт в трее и не занимает таскбар. Список окон и их назначение
сверены с `src-tauri/tauri.conf.json`; устройство самого менеджера задач
(Kanban, граф, ритуалы) — `tasks#ui`.

## analytics — Аналитика эффективности (opt-in)

part: требования
refs: tasks#cost

Питается локальными данными Claude Code (транскрипты, статистика):
кэш-эффективность и экономия от кэша, качество сессий (детект аномальных
сессий), продуктивность/ROI (стоимость активного часа, токены в минуту,
стоимость коммита/правки), разбивки по моделям и проектам, доля ошибок
инструментов, разрез по классу обслуживания, тренды и сравнение периода с
периодом, cold-rewrites с разбивкой по причинам, экспорт JSON.

Расход также разбивается по блокам исполнения — задача, сессия, интервал —
с отдельным разрезом по субагентам внутри блока: панель запуска задачи на
графе показывает стоимость и число сообщений на субагента (тип, описание,
ссылка на транскрипт) рядом с долей основного цикла, плюс остаток
(unattributed), не попавший ни в одну задачу. Стоимость задач и это
разбиение — общая граница с доменом `tasks`, подробности процесса —
`tasks#cost`.

Наружу данные не уходят — за пределы этого раздела относится opt-in канал
внешней интеграции, описанный честно в `storage`.

## auto-session — Автостарт сессии

part: требования

По сбросу 5-часового окна приложение (если включено) создаёт чат-пинг в
изолированном проекте «Usage Tracker - Auto Session», запуская новое окно;
при неудаче — повторяет. Обычные проекты не засоряются.

## releases — Обновления и релизы

part: устройство

- Автообновление через updater: манифест latest.json из GitHub Releases,
  артефакты подписаны (minisign), установка passive.
- Релиз запускается из UI: бамп версии (`npm run bump`) → тег →
  release-workflow. master закрыт для прямых пушей — только PR.
- Три изолированных профиля (dev / preview / prod) с раздельными
  data-каталогами и identifier'ами; dev-запуск — только `npm run app:dev`
  (обычный `tauri dev` писал бы в продовые данные).

## cc-integration — Интеграция с Claude Code

part: устройство
refs: tasks#plan-mode, tasks#context

- Из настроек ставится связка «CLI + хуки»: бандл-копия `cli.mjs`
  подключается в `~/.claude/settings.json` как SessionStart-хук (контекст
  доски), Stop-хук (гард handoff-батона), PostToolUse-хуки на
  EnterPlanMode/ExitPlanMode (ритуал plan mode), PreToolUse-хук на
  ExitPlanMode (формат-гард плана перед подтверждением) и
  UserPromptSubmit + PostToolUse на Read/Grep/Glob (тот же формат-гард,
  когда режим планирования включён с клавиатуры, а не вызовом инструмента).
  Устройство самого ритуала plan mode и впрыска контекста задачи —
  `tasks#plan-mode` и `tasks#context`.
- Каждый модуль `scripts/cli/*.mjs` обязан быть перечислен в
  `bundle.resources` (`src-tauri/tauri.conf.json`) — установленная сборка,
  в отличие от dev, не находит неперечисленные модули; на момент этой
  правки перечислены все 18 модулей `scripts/cli/*.mjs`, включая
  `plan-guard.mjs`, `run.mjs`, `run-step.mjs`, `adoption.mjs`, `lint.mjs`,
  `apply.mjs`, `graph-rules.mjs`, `spec.mjs`, `yaml-subset.mjs`,
  `settings.mjs`.
- Установка хуков идёт кодом (`install_cc_hook` / `heal_cc_hook` в
  `src-tauri/src/lib.rs`), не руками: пишет и чинит записи в
  `~/.claude/settings.json`, никогда не трогает чужие хуки того же события
  и никогда не устанавливает хуки, если пользователь их не запросил (кроме
  самолечения пути уже установленной связки).

## storage — Хранение и приватность

part: требования

Сессионный ключ — локально в Tauri Store; данные приложения — в
`%APPDATA%\com.claude-usage-tracker.app\` (в т.ч. todos.json).

Базовый контур (лимиты, форекаст, аналитика — разделы `limits`, `forecast`,
`analytics`) сторонним серверам ничего не отправляет: только claude.ai и
status.claude.com (`purpose`).

Это не относится ко всему приложению целиком. Вкладка интеграций
(`EnrollmentPanel`) — opt-in канал внешних задач. Resolver, на который
ходит приложение, — не хранилище-зеркало, а **балансировщик**: он принимает
задачи от внешнего источника и решает, какому устройству какую переслать.
Приложение в этой схеме — получатель: после привязки оно периодически
опрашивает resolver, предъявляя свой `device_id` и Ed25519-подпись, и
забирает адресованные ему задачи. Адрес сервера задаёт пользователь.

Канал включается явно и лежит за пределами claude.ai и status.claude.com —
поэтому старая формулировка «сторонним серверам ничего не отправляется»
была неточна для приложения в целом и заменена этой.
