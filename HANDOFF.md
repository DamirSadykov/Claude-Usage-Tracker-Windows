## 4. Правила раскладки графа

Эти правила — причина, по которой макеты читаемы. При переверстке их нельзя нарушать.

**Дорожки (кадры A, D, E, G).**
- Рельса дорожки — 196px фикс, справа `--stroke`; в ней: kicker (10px/600, uppercase, letter-spacing .13em), заголовок 13/600, прогресс, метрика.
- Колонки = волны топологического порядка. Стрелки идут только слева направо.
- **Шаг колонки минус ширина карточки = просвет.** Просвет должен вмещать подпись провода целиком. В G: карточка 196px, шаг 330px → просвет 134px под чип ≤124px. Это жёсткая связь, а не косметика.
- Кросс-дорожечная зависимость не рисуется через холст — на краю ставится порт (`.port`, круг 16px) с подписью цели.

**Стрелки.** SVG во всю площадь `.lbody`, `viewBox` = реальные пиксели контейнера, `preserveAspectRatio="none"`. Пути строятся от края карточки-источника к средней линии карточки-цели кубической кривой с горизонтальными контрольными точками. Маркер — треугольник 7×7, `refX=6`.

**Кольцевой граф (кадр C).** Фокусный узел в центре; кольца пунктиром = дистанция в переходах; за первым кольцом узлы приглушаются (`.d2`); всё дальше двух переходов — пузыри по проектам. Список связей текстом слева обязателен: читать ссылки списком быстрее, чем прослеживать кривые.

## 5. Компоненты

**Карточка задачи** (`.n`): 196–240px, радиус 9px, фон `#242424`.
Порядок: `hd` (id моно 11.5/600, `⚡`, статус-точка) → `tt` (11.6/1.35, `--text-3`) → опционально `io` (порты R/W) → опционально `cost` (подвал).
Готовая — пунктирная рамка `--ok` + текст на 42% прозрачности. Активная — фон `#2a2440`, рамка `#6b5bc4`. Выбранная — `box-shadow: 0 0 0 2px var(--accent)`.

**Подвал стоимости** (`.cost`): моно 11px, `--high`, на `rgba(0,0,0,.28)`, справа полоса 44×4px = доля в бюджете темы. Задача без прогонов показывает `$0.00 · не бралась`, а не исчезает.

**Провод с артефактом** (`.wire`, кадр G): pill, моно 10/600, **непрозрачный фон** `rgba(29,29,29,.98)` + цветная рамка по типу артефакта, `z-index:2`. Сокращённое имя на проводе, полное — в инспекторе.

**Порты R/W** (`.io i`): моно 9.5px, фон `rgba(255,255,255,.05)`, слева цветная полоса 2px — синяя для reads, зелёная для writes.

**Инспектор** (`.insp`, 170px внизу): три колонки — выбранный провод как строки DSL, карточка артефакта, сводка по типам.

**DSL** (кадр F): грид `30–38px | 1fr`, моно 12.4/1.72. Подсветка: `kw` `#c586c0` · `ar` (reads/writes/emits) `#dcdcaa` · `pa` (тип артефакта) `#9cdcfe` · `sv` `#ce9178` · `cx` комментарий `#6a9955` · `er` несуществующий артефакт `#f0a0a0` + волнистое подчёркивание. Выделенная строка — `rgba(76,194,255,.07)` + `inset 2px 0 var(--accent)`.

## 6. Модель данных (что нужно отдавать в UI)

```
artifact  { kind: spec|file|run, address, exists: bool, meta }
step      { id, title, reads[], writes[], emits[], after[], gate, stage, agent, change }
edge      выводится: writes(A) ∩ reads(B) ≠ ∅  →  ребро A→B с артефактом
run       { taskId, cost, duration, calls, tokens, errors, startedAt, agents[] }
section   { domain, slug, part, updated, refs[], mentionedFiles[], proseLines, changes[] }
```

**Рёбра не хранятся.** Зависимость выводится из совпадения имён артефактов; голое `after` — единственный ручной вид связи (в UI серый провод «после»).

Линт-правила, видимые в интерфейсе: `spec/file-missing`, `spec/two-open-changes`, `spec/prose-over-limit`, `spec/dangling-ref`, инвариант «каждый шаг change'а пишет дельту спеки либо объявляет spec unchanged».

## 7. Ловушки, на которых макеты уже ломались

1. **Коллизии имён классов.** `.n`, `.c`, `.l` — слишком короткие; в одном документе они пересеклись между карточкой узла, редактором и бейджем счётчика. В продовой вёрстке — префиксы по блоку (`graph-node`, `dsl-line`).
2. **SVG-стрелки в чужой системе координат.** `viewBox` обязан совпадать с пиксельным размером контейнера, иначе пути уезжают.
3. **Фиксированная высота карточки обрезает описание.** Использовать `min-height`, не `height`.
4. **Подпись на связи шире просвета** → перекрывает текст соседней карточки. Считать просвет до вёрстки.
5. Кадры на канвасе должны лежать в положительных координатах, иначе хост не считает габариты документа.

## 8. Что решить перед реализацией

- Какое направление берём базой графа: A (дорожки) или G (дорожки + артефакты на проводах).
- Слой прогона: отдельный режим (B) или оверлей поверх любой раскладки (E). Рекомендация — E.
- Ссылки: отдельная вкладка кольцами (C) или дорожки по разделам (D).
- DSL (F): полноценный редактор с двусторонней синхронизацией или read-only вид «показать исходник».
